## 3. 决策详细记录

### D-001 · 本次流程审计的路径与边界

- **日期**：2026-07-28
- **决策项**：如何开展“再检验整个 AI Coding 流程”
- **选项**：
  1. 临时聊天审阅，不落地
  2. `refactor-6` 步骤 0 长期调研，后续是否改造另行验收
  3. 直接修改规则与 checker
- **选择**：选项 2
- **用户原话**：「确认调研」
- **理由**：
  1. 用户要求判断“有没有核心缺陷”，需要跨规则、Hook、CI 与历史任务取证。
  2. 当前请求没有授权修改流程实现，步骤 0 应保持只审计。
  3. 流程问题跨越多个控制面，若要改造应继续经过规格、方案和任务拆分。
- **影响文件**：`research.md`、本文件、`docs/issues.md`
- **关联决策**：无

### D-002 · 后续改造方案

- **日期**：2026-07-28
- **决策项**：采用补丁式修复、状态机重建，还是彻底简化流程
- **选项**：research § 3 的方案 A / B / C
- **选择**：方案 B：单一状态机控制面
- **用户原话**：「验收步骤 0，先修两个 P0，再按方案 B 做规格。」
- **理由**：
  1. 方案 B 保留调研、TDD 和真实路径验证等有效质量机制。
  2. 单一事件真源能直接消除状态镜像漂移、commit hash 回填与多主账冲突。
  3. 相比方案 C，方案 B 可以渐进兼容历史任务，迁移风险更可控。
- **影响文件**：后续 `spec.md`、`plan.md`、治理脚本与模板
- **关联决策**：D-001

### D-003 · 实施顺序与 P0 授权

- **日期**：2026-07-28
- **决策项**：步骤 0 验收后，是直接写方案 B 规格，还是先恢复流程安全底线
- **选项**：
  1. 直接进入方案 B 规格，暂不处理 P0
  2. 先修复 F-01/F-02 两个 P0，再进入方案 B 规格
  3. 只修 P0，不继续方案 B
- **选择**：选项 2；两个 P0 使用独立 `timebox` containment 路径
- **用户原话**：「验收步骤 0，先修两个 P0，再按方案 B 做规格。」
- **理由**：
  1. 远端 Gate 失效时，新规格仍可能被绕过，必须先恢复最终裁决。
  2. 无效 Action 引用让 auto-fix workflow 在 job 前失败，属于立即可验证的阻断。
  3. containment 与控制面 v2 分离，可避免把紧急修复扩大成未验收的重构实施。
- **影响文件**：独立 P0 task、GitHub ruleset、`.github/workflows/auto-fix-ci.yml`、`scripts/ci/check_action_sha.py`、后续 `spec.md`
- **关联决策**：D-001、D-002

### D-006 · 步骤 2 五项技术决策与验收

- **日期**：2026-07-30
- **决策项**：是否采用 `plan.md` 的单一推荐及五项配套决策，并完成步骤 2
- **选项**：
  1. 全部采用推荐方案
  2. 调整一个或多个决策点后再验收
  3. 退回步骤 1 修改系统行为
- **选择**：选项 1；五项决策全部按推荐拍板：
  1. 独立受保护 `workflow-state` branch + 每事件一文件 + CAS
  2. 受限 adapter + SSH detached signature/allowed-signers + protected environment
  3. state branch projection 为权威 cache，业务分支镜像不参与 Gate
  4. 新任务原生、活跃任务逐个导入、历史任务只读
  5. Shadow 两个真实任务周期后再 Enforce，ruleset 未 active 时禁止 Enforce
- **用户原话**：「按推荐全部拍板，验收步骤 2」
- **理由**：
  1. 独立 state branch 能消除业务 commit 自引用，同时保留 Git 的审计与离线能力。
  2. Actor 签名、API 二次取证和高低权限分层满足已验收 spec 的不可自签约束。
  3. 渐进迁移与 Shadow 阶段限制爆炸半径，远端保护未生效时明确 fail closed。
- **影响文件**：`plan.md`、`task.yaml`、`research.md`、`spec.md`、`docs/issues.md`；后续 `tasks.md`
- **关联决策**：D-002、D-004、D-005
